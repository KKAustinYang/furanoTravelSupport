# バーチャルステージング デモ（MANGIRO 向け）— 開発ガイド

不動産プラットフォーム **MANGIRO**（運営：KINAKO 社）への提案用デモ。
空室の物件写真に AI が家具を配置し、Before / After で見比べられる体験を、会議室でそのまま触ってもらう。

- 実装: `demos/mangiro-staging/index.html`（単一HTML・静的デモ・ビルド不要）
- 公開URL: `/d/mangiro-staging/index.html`
- 画像生成: Modellix `google/nano-banana-pro`(t2i) / `google/nano-banana-pro-edit`(i2i)

---

## 1. 二本立て（重要）

この画面には性質の違う2つの経路がある。混ぜないこと。

| | サンプル物件3件 | アップロードした写真 |
|---|---|---|
| 画像 | **事前生成済み**（リポジトリにコミット） | **その場で生成** |
| 部屋タイプ | `manifest.json` に手書き | **LLM が写真から判定** |
| 通信 | 初回ロード後は一切なし | `/api` プロキシ経由で Modellix |
| 用途 | 商談の本番。絶対に事故らせない | 「自分の写真でも動く」を見せる |

> 商談では**必ずサンプル物件から見せる**こと。ネットワークが不安な会場でも
> ②〜⑦ が最後まで動くのはこちらだけ。アップロードは通信が生きているときの追加カード。

やってはいけないこと（引き続き）:

- サンプル物件3件を実行時生成に置き換える（会議室で失敗したら提案が死ぬ）
- サーバー側の `MODELLIX_KEY` をブラウザに渡す／`VITE_` プレフィックスを付ける
  （**お客様ご自身のキー**は別。§5-2 参照）
- Modellix の絶対URLをそのまま `fetch` する（CORS で落ちる。必ず `toProxyPath()`）
- 課金が発生する POST を盲目的にリトライする（二重課金）
- 認証・課金・回数制限の実カウント、DB 接続
- 家具の除去、家具の個別選択、動画生成
- **SNSシェア**（生成画像が広告として拡散すると不動産の表示規約の適用対象になりうる。
  「会員本人の検討用」に限定する設計）。※ **保存（ダウンロード）はクライアント判断で後から追加**。
  透かし入りのまま保存する形なので、拡散導線そのものを作らない方針は維持している
- 多言語対応・ダークモード・アナリティクス

## 2. 仕様書との差分（既存規約を優先した点）

仕様書は Next.js(App Router) + TypeScript + Tailwind、`/d/staging/` 配下を指定していたが、
このリポジトリの `demos/` は **単一HTMLの静的デモ** を並べる構成で、
`build-demos.mjs` が `demos/<slug>/` をそのまま `public/d/<slug>/` にコピーする。
仕様書 §9 の「既存の規約が優先」に従い、次のようにした。

| 仕様書 | 実装 | 理由 |
|---|---|---|
| Next.js + TS + Tailwind | 単一 HTML + CSS変数 + 素の JS | 既存の静的デモ（QNAP / property-video / tryon-aurora）と同じ粒度 |
| `/d/staging/` | `/d/mangiro-staging/` | `demos/<slug>` = 公開パスなので、スラッグに顧客名を残す |
| `public/staging/manifest.json` | `demos/mangiro-staging/staging/manifest.json` | 同上。パスは**相対**（`staging/...`）。先頭スラッシュ不可（`/d/` 配下に置かれるため） |

仕様書 §1 は「フロントエンドのみで完結する静的サイト」「実行時に画像を生成しない」と
していたが、**その後クライアント側の要望で方針変更**し、アップロード写真に限り
LLM 判定と実行時生成を入れている。サンプル物件3件は従来どおり事前生成のまま（§1 の表）。

それ以外（画面フロー、日本語文言、色、タイポグラフィ、受け入れ基準）は仕様書どおり。
**UI の日本語文言は仕様書の文字列をそのまま使っている。言い換えないこと。**

## 3. 画像の作り方

```bash
node demos/mangiro-staging/tools/generate.mjs           # 足りないものだけ生成
node demos/mangiro-staging/tools/generate.mjs --dry     # プロンプトの確認のみ（課金なし）
node demos/mangiro-staging/tools/generate.mjs --only prop-02
```

- 生成済みファイルはスキップする（冪等）。作り直したいものは **消してから** 再実行する
- `MODELLIX_KEY` はリポジトリ直下の `.env.local` から自動で読む
- 長辺 1600px の JPEG に落としてコミットする（2K 原寸だと 1 枚 3〜5MB になる）
- 1枚あたり約 **$0.12**。フルセット（空室12枚 + ステージング45枚 = 5部屋 × 3スタイル × 3パターン）で約 **$6.9**
- 以前はときどき Google の安全フィルタに弾かれていた（`Requests to remove watermarks violate...`）。
  プロンプトの透かし指示を「除去の依頼」と誤判定していたもので、**焼き込みをサーバー側に
  移してプロンプトから透かしを外したため解消**した。実行時生成の1回リトライは保険として残してある
- 依存: `sharp`（リサイズと焼き込み）。OS 依存は無い

### i2i の入力は「ローカルの original.jpg の Data URL」

Modellix の結果URLは約7日で失効する。URL を繋いで回すと後日 1 枚だけ作り直せなくなるので、
ステージングの入力には必ずローカルの `original.jpg` を Base64 Data URL 化して渡している。

### プロンプト（`staging/prompts.json` が唯一の定義）

i2i プロンプトは **RULES → STYLE → LAYOUT → QUALITY** の4ブロックを連結して作る。

- **RULES（構造保持）はコンプライアンス要件**。カメラ位置・壁・窓・扉・床材・エアコンを
  変えるなという指示が本体で、これを弱めると実在しない間取りを見せることになり、
  宅建業法上の誇大広告に該当しうる。削らない・要約しない
- **「PIXEL-ALIGNED」の段落は特に消さないこと**。「構造を変えるな」だけだと、
  モデルは部屋の造りは保ったまま**カメラを引いたり回したりする**（実際に3枚中2枚で発生した）。
  重ねたときに一致すること・消失点を動かさないこと・トリミングやズームをしないことまで
  明示して初めて視点が固定される。文言を短くしたくなったら、まずここ以外を削る
- **LAYOUT** は「1回のリクエストで3パターン」の中身。同じスタイルでも家具構成そのものを
  変えてある（会話重視 / ダイニング中心 / ラウンジ）。部屋タイプ（living / bedroom）で別セット
- **透かし・法定表記はプロンプトに書かない**。モデルに描かせると (1) 文字が崩れる
  (2) Google の安全フィルタが「透かし除去の依頼」と誤判定して生成ごと弾く、という2つの
  事故が実際に起きた。焼き込みは生成後に sharp で行う（次項）
- スタイルの `key` と `label` は `index.html` の `STYLES` と一致させる
- 文言の実体は **`staging/prompts.json`**。`tools/prompts.mjs`（事前生成）と
  `index.html`（アップロード写真の実行時生成）が**同じファイルを読む**ので、
  片方だけ直すということが起きない。`.mjs` ではなく JSON にしてあるのは、
  ブラウザから `fetch` するため（静的配信の MIME に依存させない）

## 3-2. 焼き込み（サーバー側合成・重要）

法定表記とロゴは **生成後に sharp で合成する**（`api/_stamp.js`）。守るべき点は3つ。

**① 2層に分ける。混ぜない。**

| 層 | 中身 | 差し替え |
|---|---|---|
| ① 法定表記バー | `※AIによるバーチャルステージング画像です` / `実際の物件に家具・調度品は含まれません` | **不可**（必須） |
| ② ブランドロゴ | MANGIRO ロゴ | 可（`STAGING_LOGO_DATA_URL` で上書き。再デプロイ不要） |

1枚に混ぜると、お客様がロゴを差し替えたいだけで法定表記まで消える。合成は必ず
`composite([notice, logo])` の2レイヤーで行う。

**② サイズは画像幅に対する比率で決める。px 直書き禁止。**

バー高さ `0.10w`、文字 `0.022w`、ロゴ幅 `0.17w`。解像度が変わっても見え方が変わらない。
px で書くと 4K で豆粒になり、「消費者が容易に認識できる」を満たさなくなる。

**③ 焼き込み前の画像は外に出さない。**

ブラウザが受け取るURLは常に合成後。素の生成画像を返す経路は用意していない。

```
/api/stamped/aigc/image/xxx.png
  -> https://file.modellix.ai/aigc/image/xxx.png を取得 → sharp で合成 → JPEG を返す
```

ホスト固定・GET のみ・認証ヘッダなし。パスは `[A-Za-z0-9._-/]` のみ許可し `..` を弾く。
Vite の dev でも同じ関数を呼ぶ（`vite.config.js` の `local-node-endpoints`）。
事前生成のサンプルは生成時に焼き込み済みなので、この経路を通らない。

### 焼き込みバーと、画面上の注記は別物

比較スライダーでは、焼き込んだバーの文字が **位置によって隠れる**（左寄せの文字は
Before 側に入るため、スライダーが中央だと1文字も見えない）。焼き込みは「書き出した
ファイル」のための開示なので、**画面側には別途 `.viewer-note` を常時表示している**。
どちらか一方にまとめないこと。

### 文字は実行時に描かない

`api/_stamp-assets.js` に、法定表記バーとロゴを **PNG に焼いた状態で** base64 で持っている。
実行時は幅に合わせて拡縮するだけ。理由は Vercel の実行環境に日本語フォントが無いこと。
実行時に SVG のテキストを描くと豆腐（□□□）になる。

文言・ロゴを変えたら、フォントのある端末で作り直す:

```bash
node demos/mangiro-staging/tools/make-overlays.mjs   # api/_stamp-assets.js を再生成
```

## 3-3. 焼き込みの貼り直し（ブランド変更時）

ブランド名やロゴを変えたら、**生成はやり直さず貼り直す**。

```bash
node demos/mangiro-staging/tools/make-overlays.mjs   # ① オーバーレイを作り直す
node demos/mangiro-staging/tools/restamp.mjs         # ② 既存45枚に貼り直す（費用ゼロ）
```

45枚の再生成は約 $5.5 かかるが、貼り直しなら数秒・無料で終わる。

**法定表記バーを不透明にしてあるのはこのため。** 半透明だと、すでに焼き込まれた
古いバーの文字が下から透けて残る。バーの位置と高さは画像幅からの比率で決まるので、
同じ画像に貼り直せば必ず同じ領域を覆う。透明度を下げたくなったら、貼り直しが
できなくなることを承知の上で判断すること。

`original.jpg`（空室写真＝お客様の元写真に相当）は貼り直しの対象外。

## 4. 物件・部屋の増やし方

`tools/generate.mjs` の `PROPERTIES` に足して、`tools/prompts.mjs` の `BASE_PROMPTS` に
同じキー（`prop-0X/img-0Y`）の空室プロンプトを書き、スクリプトを回す。
`manifest.json` は同じ定義から自動生成されるので手で書かない。

実案件では `original` にお客様の実写真が入り、空室写真の t2i は不要になる。

### `stageable: false` の写真を消さないこと

浴室・外観・洗面は **わざとグレーアウトして残している**。適格性判定が働いていることを
クライアントに示すのが目的で、この見せ方自体が提案材料。非表示にしない。
`rejectReason` はホバー／タップでそのまま表示する。

## 5. 画面の構造（index.html）

| 関数 | 役割 |
|---|---|
| `show(view)` | パネルの出し分け。`props / rooms / styles / gen / patterns / result` の1画面遷移 |
| `renderSteps()` / `renderSummary()` | 上部のステップ表示と、選択済み（物件・部屋・スタイル）の「変更」導線 |
| `styleExample(key)` | スタイルカードのサムネ。**選択中の部屋以外**の生成画像を使う（結果のネタバレ防止） |
| `runGeneration(isRegen)` | 約2.5秒の演出。3つのテキストを 0.8 秒ごとに切り替える。**画像を読み込みきってから**結果を出す |
| `setSplit(v)` | Before/After の分割。`clip-path: inset()` のみ。ライブラリ不使用 |
| `saveUrl(u)` / `saveBtn` | 表示中の画像を保存する。生成結果CDN（`file.modellix.ai`）は CORS ヘッダが無いので、`/api/file/*`（プロキシの読み取り中継）に付け替えてから取得する。失敗したら別タブで開く |
| `pushHistory()` / `renderHistory()` / `openRecord(r)` | 生成履歴。1回の生成＝1レコード（3パターンごと）。開くと当時の比較画面に戻る。**保存はしない**（アップロード写真の Data URL を localStorage に積むと商談中に容量エラーになりうる） |
| `renderSwitcher()` / `switchVariant(i)` | 仕上がり画面でパターンを切り替える。**比較位置は保ったまま After だけ差し替える**（スライダーが戻ると何を見比べていたか分からなくなる） |

アップロード経路の関数:

| 関数 | 役割 |
|---|---|
| `intakeFiles(files)` | 最大8枚。`shrink()` で長辺1600pxのJPEGに落とし、`classify()` に渡す |
| `classify(dataUrl)` | `/api/llm/v1/chat/completions` → `google/gemini-3.6-flash`。JSONだけを返させる |
| `applyVerdict(im, v)` | 判定結果 → `stageable` / `rejectReason`。居室（living・bedroom）かつ家具なしのみ対象 |
| `pickAspect(w,h)` | 入力に一番近い出力比を選ぶ。16:9 決め打ちは構図を切るので禁止 |
| `generateOne()` | `/api/v1/google/nano-banana-pro-edit` に投入 → `/api/v1/tasks/{id}` をポーリング |
| `runLive(isRegen)` | 3レイアウトを**並列**で生成。1枚でも成功すれば表示する |

実行時生成が3枚そろわないことがある。Google 側の安全フィルタが、透かしを**入れる**指示を
**消す**指示と誤判定して弾くため（事前生成でも45枚中2枚で発生）。同じ内容で投げ直せば通るので、
**タスクが `failed` で返ったときだけ1回リトライ**する。ネットワークが不明なまま投げ直すと
二重課金になるので、そちらはリトライしない。

`max_tokens` は 1500。このモデルは推論トークンを先に消費する（実測250前後）ので、
300 程度だと本文が出る前に打ち切られ `content` が空で返る（実際に踏んだ）。

Before/After のドラッグは、透明な `<input type="range">` を画像の上に重ねて実現している。
マウス・タッチ・キーボードが一度に片付き、実装も落ちない。ライブラリを足さないこと。

`再生成する` は経路で意味が変わる。サンプル物件は同じ3枚を並べ替えるだけの擬似動作、
アップロード写真は**本当に生成し直す**（1回 約 $0.36）。

## 5-2. APIキー（お客様ご自身の鍵で生成する）

ヘッダー右上の「APIキー」から、お客様が自分の Modellix キーを設定できる。

```
ブラウザ  →  /api/llm/... , /api/v1/...        →  api/proxy.js  →  Modellix
             X-Modellix-Key: <お客様の鍵>          そのまま中継（保存も記録もしない）
```

守ること（`demos/property-video/CLAUDE.md` と同じ方針）:

- **鍵は必ずヘッダ（`X-Modellix-Key`）で渡す。クエリ文字列に載せない**
  （URLはアクセスログ・ブラウザ履歴・Referer に残る）
- 保存先は `localStorage` のみ。サーバーには送らない・書かない・ログに出さない
- 画面には必ずマスクして出す（`mdlx-…cdef`）
- 401/403 はリトライしない。入れ直しを促す（課金前に弾かれる）
- 形式チェックはプロキシと同じ条件（印字可能ASCII 16〜200文字）

**未設定でも動く。** その場合はサーバー側の `MODELLIX_KEY`（当社負担のデモ用）に
フォールバックする。サンプル物件3件は事前生成なので、そもそも鍵を使わない。

| 状態 | ヘッダー表示 | 生成費用 |
|---|---|---|
| 未設定 | 「APIキー」（グレー） | 当社のデモ用キー |
| 設定済み | 「APIキー設定済み」（アクセント） | **お客様のアカウント** |

## 6. 受け入れ基準（仕様書 §7）

- [x] `stageable:false` はグレーアウト＋クリック不可、`rejectReason` をホバー表示
- [x] 生成中に3つのテキストが順に切り替わる
- [x] 3パターン表示 → クリックで選択。仕上がり画面からも切り替えられる
- [x] Before/After がマウスとタッチの両方で動く
- [x] 注記が生成画像の上に常時表示（削除・変更しない：コンプライアンス要件）
